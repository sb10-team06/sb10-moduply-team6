01 · OVERVIEW

핵심 결정

저장 원칙 S3 upload 성공 후 일반 object URL을 User 또는 Content 테이블에 저장합니다. API 응답 필드인 profileImageUrl, thumbnailUrl은 그대로 유지합니다.
캐시 원칙 Redis 이미지 URL 캐시는 유지합니다. 다만 Presigned URL이 아니라 DB에 저장된 URL만 캐시합니다.
  • BinaryContent와 기존 이미지 FK는 파일 상태 및 삭제 추적을 위해 유지합니다.
  • S3 업로드·삭제용 AWS SDK는 유지하고 S3Presigner만 제거합니다.
  • CloudFront, Flyway, 별도 pending 모델은 이번 범위에 포함하지 않습니다.

07 · DATA MIGRATION

기존 이미지 URL 전환

Backfill 대상 활성 이미지 FK가 연결되어 있고 BinaryContent.status='SUCCESS'인 데이터만 변환합니다. PROCESSING, FAIL, DELETED와 이미지가 없는 데이터는 null로 유지합니다.
  • URL 형식: https://{bucket}.s3.{region}.amazonaws.com/{storageKey}
  • bucket과 region은 backfill SQL에 하드코딩하지 않고 실행 시 확정합니다.
  • 검증: SUCCESS 이미지 URL 누락 0건, URL path와 storageKey 일치, 샘플 GET 성공
  • 수동 ALTER TABLE과 backfill 명령 및 실행 여부를 PR 본문에 기록합니다.
  • backfill 전 DB snapshot을 확보합니다.

PR에 기록할 운영 DB 명령

ALTER TABLE users
    ADD COLUMN IF NOT EXISTS profile_image_url TEXT;

ALTER TABLE contents
    ADD COLUMN IF NOT EXISTS thumbnail_url TEXT;

운영 환경은 ddl-auto=validate이므로 새 애플리케이션을 배포하기 전에 실행합니다.

08 · ACCESS POLICY

S3 접근 정책

Object read 이미지 object prefix에만 s3:GetObject를 허용합니다. upload와 delete는 애플리케이션 IAM 권한으로만 수행합니다.
CORS Allowed Origin은 https://moduply.co.kr, Method는 GET과 HEAD로 제한합니다.

CORS는 브라우저 교차 출처 정책이며 URL 직접 접근을 막는 보안 장치는 아닙니다. 이미지가 비공개 자산이어야 한다면 일반 S3 URL 방식과 충돌하므로 정책을 다시 결정해야 합니다.

10 · OPERATIONS

수동 DB 반영과 S3 접근 정책

애플리케이션은 DDL이나 기존 데이터 변환을 자동 실행하지 않습니다. 운영자는 배포 전에 users.profile_image_url과 contents.thumbnail_url을 추가하고, 실제 bucket·region으로 SUCCESS 데이터만 backfill합니다. 동일 SQL은 PR의 기타 참고 사항에 기록합니다. 

\set ON_ERROR_STOP on

BEGIN;
SET LOCAL lock_timeout = '5s';

ALTER TABLE users
    ADD COLUMN IF NOT EXISTS profile_image_url TEXT;

ALTER TABLE contents
    ADD COLUMN IF NOT EXISTS thumbnail_url TEXT;

COMMIT;

UPDATE users AS u
SET profile_image_url = format(
    'https://%s.s3.%s.amazonaws.com/%s',
    '<bucket>', '<region>', bc.storage_key
)
FROM binary_contents AS bc
WHERE u.profile_img_id = bc.id
  AND bc.status = 'SUCCESS'
  AND u.profile_image_url IS NULL;

UPDATE contents AS c
SET thumbnail_url = format(
    'https://%s.s3.%s.amazonaws.com/%s',
    '<bucket>', '<region>', bc.storage_key
)
FROM binary_contents AS bc
WHERE c.content_img_id = bc.id
  AND bc.status = 'SUCCESS'
  AND c.thumbnail_url IS NULL;

운영 반영 순서

  1. 프로필·콘텐츠 이미지 신규 등록과 교체 요청을 일시 중지합니다.
  2. URL 컬럼 ALTER TABLE을 실행합니다.
  3. 이미지 공개 GET과 moduply.co.kr CORS 정책을 적용합니다.
  4. SUCCESS 이미지 URL backfill을 실행합니다.
  5. 활성 SUCCESS 이미지 중 URL null이 0건인지 검증하고 샘플 GET을 확인합니다.
  6. Redis v4 prefix를 사용하는 새 애플리케이션을 배포합니다.
  7. 이미지 쓰기를 재개합니다.

backfill 검증보다 새 애플리케이션 배포가 먼저 진행되면 기존 이미지는 null 또는 placeholder로 보일 수 있으므로 이 순서를 바꾸지 않습니다.

S3 CORS는 https://moduply.co.kr의 GET·HEAD만 허용합니다. CORS 자체는 객체 읽기 권한을 만들지 않으므로 이미지 prefix의 s3:GetObject 정책과 Block Public Access 설정도 함께 확인합니다.

bucket·region·배포 도메인 변경 시에는 URL null 대상 backfill이 아니라 기존 URL prefix를 조건으로 SUCCESS 전체를 재작성하고, imageUrl·contentList·contentDetail·playlistDetail 캐시를 제거합니다. Redis eviction 장애 시 DB/S3 성공 상태는 유지되며 stale 응답은 TTL상 최대 5분까지 허용합니다. 

[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedOrigins": ["https://moduply.co.kr"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
